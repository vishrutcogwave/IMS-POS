# Restaurant POS implementation contract

Original application: Hearth Table. Base path `/api`. JSON entity keys use database snake_case, request records use camelCase as specified. UUID identifiers. Monetary values are decimal rupees (never trust client totals). List responses are JSON arrays unless a paginated report. Dates ISO-8601. Error shape `{code,message,requestId}`. Request ID optional. All writes require X-CSRF-Token obtained from login/me; browser uses HttpOnly session cookie and credentials include. No localStorage tokens. Mutating financial/print actions additionally require `Idempotency-Key` UUID, retained on retries. No protected endpoint accepts tenantId.

## Foundation Java contract
Package `com.restaurant.pos`. Java 21 / Spring Boot 3.4. Spring JDBC + PostgreSQL + Flyway. Existing V1 migration is authoritative; do not casually change its columns. `Actor(UUID tenantId, UUID userId, String role, String name, String email)` record, `Actor.current()` reads request authentication. `Actor.require(String permission)` throws forbidden. Permissions: DASHBOARD, ORDER, DISCOUNT, TRANSFER, KITCHEN, BILL, CANCEL, REPORT, SETTINGS, USERS, PRINT. OWNER/MANAGER all except MANAGER cannot manage OWNER; CASHIER DASHBOARD ORDER BILL PRINT; WAITER ORDER TRANSFER PRINT; KITCHEN KITCHEN PRINT; ACCOUNTANT DASHBOARD REPORT PRINT.

`TenantJdbc` component exposes `public <T> T tx(Actor a, Supplier<T> work)`, and `public <T> T asTenant(UUID id,Supplier<T> work)` for onboarding/login. Runs Spring TransactionTemplate, sets transaction-local app.tenant_id. `public JdbcTemplate jdbc()` exposes template. `public List<Map<String,Object>> list(String sql,Object...args)` and `public Map<String,Object> one(String sql,Object...args)` convert JDBC UUID to strings, Timestamp to ISO string, PGobject JSON to decoded JSON, SQL arrays to lists; one throws 404 when absent. `public int update(String sql,Object...args)`. `public String json(Object value)`. `public void outlet(Actor a,UUID outletId)` verifies same-tenant outlet and either OWNER or user_outlets access; MANAGER needs assigned outlet. `public void audit(Actor a,UUID outletId,String action,String entityType,UUID entityId,String reason,Object details)`. Every SQL query also explicitly restricts tenant_id; RLS is defense in depth. `ApiException(int status,String message)`. Auth controller is permitted publicly only login, CSRF handshake not needed for login since JSON+same-origin, onboarding gated by server env secret sent in X-Onboarding-Key. Sessions expire in 12h; random 256-bit token stored only as SHA256; password BCrypt. Invalidate all sessions after password changes. Spring filters reject CSRF and unauthorized API, deny cross-origin writes, security headers. Auth sessions are globally hash-looked-up then trusted tenant resolves user under tenant transaction. Do not expose hashes/session tokens.

## Authentication
`POST /auth/login {tenantSlug,email,password}` -> `{user:{id,name,email,role,permissions:string[]},tenant:{id,name,slug,...},outlets:[...],csrfToken}` sets cookie. `GET /auth/me` same envelope. `POST /auth/logout` -> `{ok:true}`. `PATCH /auth/profile {name}`. `POST /auth/password {currentPassword,newPassword}`. `POST /auth/onboard {businessName,slug,name,email,password}` with server-approved X-Onboarding-Key -> `{slug}` creates tenant, owner, branch, outlet and access. No public signup without env-configured onboarding key.

## Catalog / setup
`GET /catalog?outletId=UUID` -> `{categories:[],items:[],tables:[],printers:[],routes:[],outlet:{...}}`. tables include active_order_id, order_status when occupied. category has department; item variants and modifiers arrays of `{name,price}` (variant price is absolute; modifier price additive). Items include vegetarian. `GET /settings` -> `{tenant,branches,outlets,users,categories,items,tables,printers,routes}` filtered accessible outlets; settings/users may be empty or forbidden if role lacks appropriate permissions; `/catalog` usable by ORDER/BILL/KITCHEN/PRINT roles. Users contain assigned `outlet_ids`, never hashes. `PATCH /settings/business {name,receiptAddress,taxNumber,phone,receiptFooter}`.
`POST /settings/branches {name,address}`.
`POST /settings/outlets {branchId,name,serviceModes:string[],paymentMethods:string[],currency,timezone}`; `PUT /settings/outlets/{id}` same.
`POST /settings/users {name,email,password,role,outletIds:string[]}`; `PUT /settings/users/{id} {name,email,role,outletIds,active}`; user privileges and session revocation enforced. OWNER creation/edit OWNER requires OWNER.
`POST /settings/categories {outletId,name,department,sortOrder}`; `PUT /settings/categories/{id}` same.
`POST /settings/items {outletId,categoryId,name,description,price,taxRate,available,vegetarian,variants:[{name,price}],modifiers:[{name,price}]}`; `PUT /settings/items/{id}` same.
`POST /settings/tables {outletId,name,section,seats}`; PUT same.
`POST /settings/printers {outletId,name,deviceKey,documentType,paperWidth,copies,enabled,isFallback,isReceipt,template}`; PUT same. Only local device aliases, never remote host executable configuration. `PUT /settings/routes {outletId,routes:[{categoryId,printerId}]}` replace routes atomically, same outlet and KOT-capable enabled printer validation. Responses created/updated entity `{id,...}` or `{ok:true}`.

## Restaurant operations
All use authenticated Actor and TenantJdbc tx. Every ID relationship validates same tenant + outlet access; rows locked `FOR UPDATE`, version mismatch 409. Failed printing never rolls back already accepted ticket: durable print job is transactionally saved, physical print separate. Every price/tax/modifier validated from menu server-side; immutable line snapshots.
`GET /orders?outletId=UUID&status=active` -> order array with totals and `items` (optional items for list; detail always). `GET /orders/{id}` -> order with `items`, `kots`, `bills`, `subtotal,tax,total`, rows snake_case.
`POST /orders {outletId,serviceMode,tableId?,covers,notes,customerName}` -> detail. Active table uniqueness. Requires ORDER.
`POST /orders/{id}/items {version,menuItemId,quantity,variant,modifiers:string[],notes}` -> detail. Each new line distinct UUID. Incremental kitchen send operates sent_quantity. Cannot edit already sent line; cancellation explicit.
`PATCH /orders/{id} {version,notes,customerName,discount}` -> detail; DISCOUNT permission for discount changes only, discount amount <= subtotal; open orders only.
`PATCH /orders/{id}/items/{itemId} {version,quantity,notes}` -> detail; may edit only unsent line.
`POST /orders/{id}/items/{itemId}/cancel {version,reason}` -> detail; only unsent line cancellation; sent line use KOT cancellation to keep kitchen and financial records consistent.
`POST /orders/{id}/transfer {version,tableId,reason}` -> detail. Same outlet, active table uniqueness, audit.
`POST /orders/{id}/cancel {version,reason}` -> detail. CANCEL permission, refuse if paid bills; void open bills and issue kitchen cancellation jobs; release table.
`POST /orders/{id}/send {version}` -> detail; Idempotency-Key. Route ALL unsent items first; missing mapping/fallback => 422 and no changes; grouped printer-specific KOTs/jobs with item snapshot and sent_quantity increment; bump version.
`POST /orders/{id}/bills {version,groups?:[{items:[{itemId,quantity}]}]}` -> detail; creates one bill for all items or item/quantity split groups exactly covering all active items; require all items sent and no noncancelled bills; discount proportionally allocated with cent remainder deterministic; snapshot per bill. Bump order version status BILL_PENDING. BILL permission.
`GET /kots?outletId=UUID` -> tickets with items, order_number, table_name, service_mode.
`POST /kots/{id}/status {status}` transitions QUEUED->PREPARING->READY->SERVED only; KITCHEN permission.
`POST /kots/{id}/cancel {reason}` -> ticket; CANCEL permission, cancels all ticket quantities in order active lines; refuse billed order; clone/split line when partial qty to retain clean snapshots; preserve original KOT and cancellation print job. May choose to refuse partial quantity scenario if preserving original exact ticket quantities can be implemented directly. All tickets consist of immutable newly added lines since sent lines cannot edit.
`POST /kots/{id}/reprint {reason}` -> print job, PRINT permission original reference mandatory; Idempotency-Key.
`GET /bills?outletId=UUID` -> bills with order_number. `GET /bills/{id}` -> bill with items, payments, tenant receipt details, outlet, order.
`POST /bills/{id}/settle {version,payments:[{method,amount,reference}],cashTendered?}` -> bill with `change`; BILL permission; sum payments must equal bill total, configured methods only, CARD/UPI reference required (manual external confirmation, NOT payment-gateway integration); cashTendered >= cash allocation; statuses and all writes atomic; last bill paid settles order/releases table. Durable receipt job requires configured receipt printer. Idempotency-Key.
`POST /bills/{id}/cancel {version,reason}` -> bill; CANCEL permission; only unpaid bills (paid refund/reversal not implemented; reject clearly). Cancel all unpaid sibling bills atomically when reopening split order; disallow if any sibling already paid. Reopen order for audited edits. Explicit audit BILL_CANCEL.
`POST /bills/{id}/modify {version,reason,discount}` -> bill; DISCOUNT+CANCEL permissions; unpaid standalone bill only, total recalculation from immutable items, audit BILL_MODIFY; split bill modifications require cancel/regenerate.
`POST /bills/{id}/reprint {reason}` -> job; PRINT permission, immutable receipt snapshot with original bill reference; Idempotency-Key.

## Printing
`POST /printing/preview {outletId,items:[{menuItemId,quantity}]}` -> `{groups:[{printer,items}],unmapped:[]}`; no writes, no silent drops.
`GET /printing/jobs?outletId=UUID` -> last 100 jobs with printer_name, device_key. PRINT permission.
`POST /printing/printers/{id}/test {}` -> queued TEST job. PRINT permission.
`POST /printing/jobs/{id}/retry {reason}` -> a new job retaining original_job_id, only FAILED/UNCERTAIN; reason must contain "duplicate" to explicitly acknowledge possible duplicate output. Never automatic retry after uncertain physical output.
Print agent uses a dedicated low-privilege KITCHEN account assigned ONE outlet, same login/CSRF session and tenant resolved server-side. `POST /printing/claim {outletId,deviceKeys:string[]}` -> `{jobs:[]}`; claim one PENDING job at a time to stay within the transport lease scoped user outlet plus device allowlist, `FOR UPDATE SKIP LOCKED`, unique random claim_token; set CLAIMED and attempts. Return device_key, paper_width, copies, template, and immutable payload with `title,reference,outlet,order,table,createdAt,lines:[{name,quantity,unitPrice?,modifiers?,notes?}],subtotal?,discount?,tax?,total?,footer?,address?,taxNumber?`.
`POST /printing/jobs/{id}/ack {claimToken,status,error}` -> job; status PRINTED/FAILED/UNCERTAIN; must match claimant user and token, update printer last_seen. Jobs claimed >120 seconds become UNCERTAIN during tenant-scoped queue read/claim (no global cross-tenant scheduler). PRINTED means transport accepted, not paper sensor confirmation. Browser receipt rendering can show immutable receipt but not mark hardware jobs done.

## Dashboard / reports
`GET /dashboard?outletId=UUID&from=YYYY-MM-DD&to=YYYY-MM-DD` -> `{sales,billCount,averageBill,activeTables,activeOrders,payments:[{method,total}],topItems:[{name,quantity,total}],topCategories:[{name,total}],outlets:[{name,total}],daily:[{date,total}]}`. Defaults today in outlet timezone, inclusive local dates converted to UTC; settled receipts only.
`GET /reports/{type}?outletId=UUID&from=...&to=...&page=0&size=25` -> `{rows:[],totalElements,page,size,totals:{...}}`. Types `daily-sales,item-sales,category-sales,outlet-sales,payments,kot-register,kot-cancellations,bill-reprints,bill-cancellations,bill-modifications,table-activity,tax-settlement`. REPORT permission. All queries use explicit tenant AND accessible outlet, whitelisted type. CSV export same filters `/reports/{type}/export`, formula escaping, maximum bounded date range (366 days) and row count with explicit error not silent truncation. Dates and pagination validated.
